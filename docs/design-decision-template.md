# 디자인 결정 기록

화면·컴포넌트·팔레트·서체·공유 자산을 만들 때 이 파일을 복사해 채운다. 토큰 규칙은 [DESIGN.md](../DESIGN.md), 레퍼런스를 고르는 방법은 [design-references.md](design-references.md)를 따른다. 판단 근거를 남기는 것이 목적이고, 형식에 맞추기 위한 문장은 늘리지 않는다.

## 양식

```markdown
# 디자인 결정: <제목>

- 날짜·작성자:
- 대상 화면/문서·사용자·플랫폼·viewport:
- 제약: DESIGN.md 토큰, 접근성, 성능, 라이선스
- 검토한 레퍼런스: 링크, checked_at, 라이선스, 선택 이유
- 선택지와 장단점:
- 결정:
- 토큰 매핑: 기존 토큰 재사용 / 신규 토큰과 근거
- 영향: 반응형, 키보드·포커스, 명암비, 폰트 로딩, 공유 미리보기
- 검증: 명령·스크린샷·Lighthouse 기준선·미검증 항목
- 예외·위험:
```

## 작성 기준

- 검토한 레퍼런스에는 링크와 `checked_at`을 함께 적는다. 라이선스를 확인하지 않았으면 `확인 필요`로 적는다.
- 선택지와 장단점에는 버린 대안과 버린 이유를 넣는다.
- 토큰 매핑은 기존 토큰 재사용을 기본으로 한다. 새 토큰은 근거와 변경 영향을 함께 적는다.
- 검증 항목에는 실행한 명령, 남긴 스크린샷, Lighthouse 기준선을 구분해 적는다. 실행하지 않은 것은 미검증으로 남긴다.
- 예외·위험에는 확인하지 못한 항목과 남은 위험을 그대로 적는다. 지우지 않는다.

## 보관

기록은 작업한 이슈나 PR 설명에 붙인다. 이 저장소에는 화면 샘플 앱이 없어 결정 기록만으로 동작을 증명하지 않는다.
