# 모델별 운용 기록

2026년 10월 20일의 운영에서 남긴 모델별 관찰을 한곳에 모았습니다. 대상 저장소는 moi, yoroi, the-great-dalmuti 세 곳입니다. 어떤 모델이 좋은지를 가리는 글이 아닙니다. 다음 운영을 준비하는 사람이 같은 시행착오를 줄이도록 돕는 기록입니다.

이 글의 한계를 먼저 밝힙니다. 단일 날짜, 서로 다른 작업, 작은 표본의 정성 기록이며, 통제된 비교나 벤치마크가 아닙니다. 모델 버전과 제공자 정책은 계속 바뀌므로, 아래 내용은 작성일 기준의 인상과 그때 유효했던 대응으로 읽어 주세요. 관찰과 권고를 구분해서 적었고, 비용 이야기는 정성 표현으로만 담았습니다.

## 관찰된 교훈

서로 다른 모델이 리뷰하면 서로 다른 종류의 결함이 잡혔습니다. 작성자와 같은 계열이 리뷰하면 함께 놓치기 쉬운 지점이 있습니다. 플랫폼별 차이, 깨진 링크, 오래된 이름이 교차 리뷰에서 걸러졌습니다. 이는 특정 모델의 우열이 아니라, 관점을 섞는 구조의 효과로 보입니다.

리뷰어의 쿼터가 떨어지면 작업이 멈추지 않도록 다른 모델이 같은 형식으로 리뷰를 이어받았습니다. 이때 리뷰·증거 형식을 그대로 유지한 것이 중요했습니다. 형식이 같으니 이어받은 리뷰의 판정을 그대로 신뢰할 수 있었기 때문입니다.

테스트가 모두 초록이어도 화면의 문제는 스크린샷에서만 보였습니다. 버튼 테두리, 이중 불릿, 링크 색 같은 디테일은 게이트 통과와 별개였습니다. 캡처와 계산된 스타일 측정을 수락 절차에 고정한 것이 실질적인 대비였습니다.

무료·프리뷰 계열은 작은 초안과 리뷰에 잘 맞았습니다. 상태를 오래 유지하는 작업은 더 강한 모델에 두는 편이 안정적이라는 관찰이 반복됐습니다. 모델을 고르는 기준은 가격이 아니라 작업의 상태 크기였습니다.

화면이 조용해졌다고 일이 끝난 것은 아니었습니다. 대기 명령이 반환되거나 세션이 사라진 경우가 있었습니다. durable 보고서와 커밋 SHA가 없으면 완료로 인정하지 않는 원칙이 허위 확신을 막았습니다. 보고서를 먼저 쓰고 증명으로 확인하는 순서가 핵심입니다.

역할 이름은 현재 역할을 가리키는 것이 좋고, 모델·세션 변경은 사용자의 결정에 따랐습니다. 다음 운영에서는 시간·토큰·재작업·flake 지표를 단위별로 기록하면 좋겠습니다. 하루의 인상을 비교 가능한 형태로 발전시킬 수 있을 것입니다. 단, 하루의 기록을 순위로 바꾸지는 않기로 합니다.
